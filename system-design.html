2. Entity Relationship Diagram

Six MongoDB collections. Users own wallets, transactions, categories, expenses, budgets and notifications.

USER
role · status · pin · profilePicture
1 ── owns ── 1
WALLET
balance
1 ── has ── N
TRANSACTION

USER
role · status · pin · profilePicture
1 ── creates ── N
CATEGORY
name · userId (global optional)
1 ── N
EXPENSE
categoryId · amount · date · month · year
USER
role · status · pin · profilePicture
1 ── sets ── N
BUDGET
amount · month · year (unique per user+month)
1 ── receives ── N
NOTIFICATION
message · read · userId
Cardinality summary: User 1:1 Wallet · User 1:N Transaction · User 1:N Category · Category 1:N Expense · User 1:N Notification · User 1:N Budget (unique per month).

6. Real-Time Notification Flow

Redis decouples producers from consumers, letting multiple backend instances share one notification bus.

Controller Action
e.g. send-money succeeds
▼
publishNotification()
Redis PUBLISHER
▼
Redis CHANNEL "notifications"
▼
Redis SUBSCRIBER (app.js message handler)
▼
emitNotificationToUser()
Socket.IO server
▼
io.to(userId).emit("new_notification")
▼
Browser Client
socketService.js listener
▼
Redux notificationSlice update
▼
React Hot Toast popup
Why Redis? The Socket.IO Redis adapter lets a user's WebSocket be reachable from any backend instance; the pub/sub channel fans notifications out across instances — enabling horizontal scaling.
