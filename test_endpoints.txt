To test the `PUT /api/admin/user/:userId/freeze` endpoint, follow these steps:

**Prerequisites:**
1.  A running instance of the application.
2.  Access to the database to verify user status.
3.  An existing "admin" user with a valid authentication token.
4.  At least one existing "regular" user (not an admin).

**Test Cases:**

**Test Case 1: Successfully freeze a user account**
1.  **Obtain Admin Token:** Log in as an admin user to get an authentication token.
2.  **Identify Target User:** Select a regular user's `userId` from the database. Ensure their current `status` is 'active'.
3.  **Send Request:**
    *   **Method:** `PUT`
    *   **URL:** `/api/admin/user/:userId/freeze` (replace `:userId` with the actual ID of the target user)
    *   **Headers:**
        *   `Authorization: Bearer <admin_token>`
    *   **Body:** (Empty or optional, depending on implementation; usually not needed for a freeze endpoint)
4.  **Verify Response:**
    *   **Status Code:** Expect `200 OK`
    *   **Body:** Expect a success message, e.g., `{"message": "User account frozen successfully"}` (exact message may vary).
5.  **Verify Database:** Check the database to confirm that the target user's `status` has changed from 'active' to 'inactive'.

**Test Case 2: Attempt to freeze with a non-admin token**
1.  **Obtain User Token:** Log in as a regular user to get an authentication token.
2.  **Identify Target User:** Select a regular user's `userId`.
3.  **Send Request:**
    *   **Method:** `PUT`
    *   **URL:** `/api/admin/user/:userId/freeze`
    *   **Headers:**
        *   `Authorization: Bearer <regular_user_token>`
4.  **Verify Response:**
    *   **Status Code:** Expect `403 Forbidden`
    *   **Body:** Expect an access denied message, e.g., `{"msg": "Access denied: Not an administrator"}`.

**Test Case 3: Attempt to freeze a non-existent user**
1.  **Obtain Admin Token:** Log in as an admin user to get an authentication token.
2.  **Use Invalid UserId:** Use a `userId` that does not exist in the database (e.g., a randomly generated valid-looking ID).
3.  **Send Request:**
    *   **Method:** `PUT`
    *   **URL:** `/api/admin/user/:invalidUserId/freeze`
    *   **Headers:**
        *   `Authorization: Bearer <admin_token>`
4.  **Verify Response:**
    *   **Status Code:** Expect `404 Not Found`
    *   **Body:** Expect a user not found message, e.g., `{"message": "User not found"}`.

**Test Case 4: Attempt to freeze an already frozen user (optional, depending on desired behavior)**
1.  **Pre-freeze User:** Manually set a regular user's `status` to 'inactive' in the database, or use Test Case 1 to freeze them.
2.  **Obtain Admin Token:** Log in as an admin user.
3.  **Send Request:**
    *   **Method:** `PUT`
    *   **URL:** `/api/admin/user/:alreadyFrozenUserId/freeze`
    *   **Headers:**
        *   `Authorization: Bearer <admin_token>`
4.  **Verify Response:**
    *   **Status Code:** Expect `200 OK` (if idempotent) or potentially `400 Bad Request` with a message like "User already frozen". The implementation of `freezeUserAccount` will determine the exact response.
    *   **Body:** Appropriate message.
5.  **Verify Database:** Confirm the user's `status` remains 'inactive'.

**Test Case 5: Attempt to freeze an admin user (optional, depending on business rules)**
1.  **Obtain Admin Token:** Log in as an admin user.
2.  **Identify Target User:** Select an admin user's `userId`.
3.  **Send Request:**
    *   **Method:** `PUT`
    *   **URL:** `/api/admin/user/:adminUserId/freeze`
    *   **Headers:**
        *   `Authorization: Bearer <admin_token>`
4.  **Verify Response:**
    *   **Status Code:** Expect `400 Bad Request` or `403 Forbidden` if freezing admins is not allowed, or `200 OK` if it is.
    *   **Body:** Appropriate message.
5.  **Verify Database:** Check if the admin user's status changed (if allowed).
