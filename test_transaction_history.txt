Here is a review of your `getTransactionHistory` method and instructions on how to test it.

### Method Review & Correction

Your original `getTransactionHistory` method was attempting to find transactions through the `Wallet` model, but the `Wallet` model did not have a reference to the `Transaction` model. This would have resulted in an empty list being returned.

I have corrected the implementation to query the `Transaction` collection directly, which is the correct approach. The updated function now finds all transactions where the user is either the sender (`fromUser`) or the receiver (`toUser`) and sorts them with the newest transactions first.

---

### How to Test the `GET /api/auth/history` Endpoint

**Prerequisites:**
1.  A running instance of the application.
2.  At least two registered users (e.g., User A and User B) to perform transactions.
3.  You have performed some transactions between these users. For example:
    *   User A sends money to User B.
    *   User B sends money back to User A.

**Test Case 1: Successfully fetch transaction history**
1.  **Log In:** Log in as User A to get a valid authentication token.
2.  **Send Request:**
    *   **Method:** `GET`
    *   **URL:** `/api/auth/history`
    *   **Headers:**
        *   `Authorization: Bearer <user_a_token>`
3.  **Verify Response:**
    *   **Status Code:** Expect `200 OK`.
    *   **Body:** The response body should be a JSON object containing a `transactions` array.
    *   **Verify Content:**
        *   Check that the `transactions` array contains objects for the transactions you performed.
        *   Confirm that for each transaction, the `fromUser` and `toUser` fields are populated with the name and email of the respective users.
        *   Verify that the transactions are sorted in descending order of creation time (most recent first).
        *   Ensure that only transactions involving User A are present.

**Test Case 2: Fetch history for a user with no transactions**
1.  **Create a New User:** Register a new user (e.g., User C) who has not been involved in any transactions.
2.  **Log In:** Log in as User C to get their authentication token.
3.  **Send Request:**
    *   **Method:** `GET`
    *   **URL:** `/api/auth/history`
    *   **Headers:**
        *   `Authorization: Bearer <user_c_token>`
4.  **Verify Response:**
    *   **Status Code:** Expect `200 OK`.
    *   **Body:** The `transactions` array in the response should be empty (`[]`).

**Test Case 3: Attempt to fetch history without authentication**
1.  **Send Request:**
    *   **Method:** `GET`
    *   **URL:** `/api/auth/history`
    *   **(No Authorization Header)**
2.  **Verify Response:**
    *   **Status Code:** Expect `401 Unauthorized`.
    *   **Body:** Expect an error message indicating that the request is unauthorized.
